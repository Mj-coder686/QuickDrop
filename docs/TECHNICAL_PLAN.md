# QuickDrop MVP 技术方案

## 1. 产品目标

QuickDrop 是面向学生的临时设备直传工具，不是网盘。用户只需要：

1. 发送端选择文件或文件夹，获得 6 位数字码。
2. 接收端输入数字码。
3. 发送端确认对方设备。
4. 文件在两台设备之间直接传输。

MVP 主路径是 Windows ↔ Windows 、同一局域网高速直传。台式机插网线、笔记本连 Wi-Fi 时，只要校园网允许两端互访，也走同一条局域网路径。

## 2. MVP 范围

### P0：必须可用

- 6 位随机配对码，会话默认 10 分钟后失效。
- UDP 组播 + IPv4 广播自动发现，无需输入 IP。
- TCP + TLS 加密传输，每次会话使用临时证书。
- 发送端显式确认接收设备。
- 多文件和整个文件夹，保留相对目录结构。
- 1 MiB 分块流式传输，不把大文件整体读入内存。
- `.qdpart` 临时文件 + 位置记录实现断点续传。
- SHA-256 完整性校验，校验通过后才原子更名为正式文件。
- 进度、实时速度、剩余时间、当前文件、取消。
- 单文件校验失败自动重试一次，会话失败后可点击重试并利用断点。

### P1：为后续保留接口

- `IRouteProvider`：当前只实现 LAN，以后增加 WebRTC/QUIC/STUN/TURN。
- `ITransferConnection`：传输核心不依赖 WPF 和具体套接字。
- 协议带版本号、平台字段和能力列表，为 Android 互通预留扩展点。

### P2：不在本次实现

- 公网 NAT 穿透、TURN 中继、中心配对服务。
- Android 客户端。
- 多接收端广播、长期设备信任、账号和云端存储。

## 3. 架构与依赖

```text
QuickDrop.App (WPF / MVVM)
        │
        ├─ QuickDrop.Core
        │    ├─ 会话、清单、进度模型
        │    ├─ 文件列举、安全路径、SHA-256
        │    └─ 路由/传输抽象
        │
        └─ QuickDrop.Network
             ├─ LAN 会话广告与发现
             ├─ TLS 临时证书与指纹固定
             ├─ 长度前缀帧协议
             └─ 发送/接收编排器

QuickDrop.Tests (Console test runner)
        └─ 单元测试 + 回环端到端测试
```

依赖只使用 .NET 8 自带库，不引入第三方 NuGet 包，便于学校电脑离线运行和自包含发布。

## 4. 自动路径选择

```text
输入短码
   │
   ├─ 搜索 LAN 广告 ─成功→ TLS/TCP 局域网直传
   │
   └─ 超时 ─→ 返回“未找到设备”
                    └─ 后续版本：向配对服务查询→公网 P2P→中继
```

UI 只显示“局域网直连”或友好错误，不要求用户理解 IP、网段、Wi-Fi 或网线。

## 5. 协议流程

1. 发送端生成 `SessionId`、6 位码、随机盐、临时 TLS 证书。
2. 定时发送局域网广告；广告只含短码派生标签，不含明文短码。
3. 接收端计算标签匹配会话，按广告的证书 SHA-256 指纹固定 TLS 连接。
4. 接收端发送含随机数的 HMAC 配对证明和设备信息。
5. 发送端校验、限制尝试次数，并弹窗要求用户确认设备。
6. 发送文件清单；接收端回复每个文件已有的 `.qdpart` 字节数。
7. 逐文件、逐分块传输；两端流式计算 SHA-256。
8. 接收端校验成功后更名，回复 ACK；失败则从 0 自动重试一次。

## 6. 安全边界

- 数字码是临时配对信号，不是长期密码。
- 会话超时、单接收端、失败尝试上限和人工设备确认共同限制 6 位码被枚举的风险。
- 路径规范化并校验必须位于目标根目录内，阻止 `../` 路径穿越。
- 不覆盖已存在的完整文件；同名时创建带序号的新文件。
- 取消或断网只保留 `.qdpart` 临时文件，不暴露半成品为正式文件。

## 7. 验收标准

- 解决方案可在无第三方包条件下构建。
- 单元测试覆盖：短码格式与随机性、配对证明、安全路径、清单列举、协议帧、进度计算。
- 回环端到端测试覆盖：正常传输、文件夹、SHA-256 相等、人为中断后续传。
- WPF 应用可启动，发送与接收主流程可操作。
- 输出 Windows x64 自包含发布目录和一键启动脚本。
